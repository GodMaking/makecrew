# Product Delivery

Use this Skill for new or substantially redesigned websites, apps, products,
and multi-stage features. Keep small bug fixes, routine edits, and simple
queries on the shorter `task-intake` path.

## Workflow

1. Read the project rules, existing context, repository status, and startup/test commands.
2. Clarify material gaps until the target, users, scope, constraints, and acceptance criteria are decision-ready.
3. Produce a compact `project-brief.md` with the goal, users, scope, non-goals, and measurable acceptance criteria.
4. Produce a `product-demo.md` describing the core flow, states, and a minimal prototype or preview when useful.
5. Produce a `technical-design.md` covering architecture, interfaces, data, dependencies, risks, and reversible choices.
6. List the matched Skills, tools, employees, deliverables, budget, and verification gates. Wait for confirmation before implementation when the plan changes scope or cost.
7. Implement incrementally, keeping changes scoped to the approved plan and recording checkpoints.
8. Run tests and verify the key user flow in the target environment. Record fresh evidence in `verification-report.md`.
9. Present the delivered artifact, evidence, known limits, rollback point, and next action.

## Context and cost

Reuse the project context and employee thread where compatible. Pass task deltas,
not complete histories. Do not run this full workflow for routine maintenance.

## Output contract

Return the approved scope, selected Skills/tools, artifacts, checkpoints,
verification evidence, risks, and delivery status. A plan or queued host task
is not a completed delivery.
