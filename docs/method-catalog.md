# 方法卡目录

MakeCrew 的方法卡是任务级的轻量决策提示，不是强制工作流，也不是额外的
Skill 安装包。路由器只在任务清楚后加载当前领域的元数据；详细 Skill 指令、
参考资料和脚本仍遵循渐进式披露。

## 当前方法卡

| 方法 ID | 领域 | 解决的问题 | 主要产出 |
|---|---|---|---|
| `engineering-spec-incremental` | 工程 | 在已有项目中小步实现并回归 | 实现、测试、变更说明 |
| `product-delivery-gates` | 工程 | 新建或重做产品前先确认范围 | 简报、Demo、技术设计、验收报告 |
| `research-source-first` | 研究 | 让结论有可追溯来源 | 结论、来源、日期、不确定性 |
| `research-theory-case-counterexample` | 研究 | 用理论、同构案例和反例解释复杂判断 | 直接答案、理论表、案例矩阵、适用边界 |
| `benchmark-transferability` | 研究 | 区分可迁移机制与表面模仿 | 候选对象、筛选理由、验证动作 |
| `content-audience-first` | 内容 | 让一条内容围绕一个受众问题和承诺 | 受众问题、单一承诺、平台版本 |
| `content-asset-map` | 内容 | 把大量素材变成可追溯、可重组资产 | 素材清单、内容单元、主题关系、草稿 |
| `content-two-layer-review` | 内容 | 分开检查机器信号和内容实质问题 | 定位、原因、最小修改动作 |
| `knowledge-scope-sample` | 知识库 | 先盘点范围，再用抽样验证质量 | 范围报告、索引计划、抽样结果 |
| `knowledge-navigation-incremental-audit` | 知识库 | 用导航、原件和增量同步维护共享记忆 | 导航、来源关系、同步记录、冲突报告 |
| `design-hierarchy-size-check` | 设计 | 在目标尺寸验证信息层级和关键交互 | 预览、组件约束、可访问性检查 |
| `skill-trigger-contract` | 技能 | 用行为契约减少误触发和漏触发 | SKILL.md、正例、近邻反例、回归结果 |

每张方法卡的字段：

- `method_id`：稳定标识，方便日志、评测和自进化提案引用；
- `when_to_use`：适用信号，不是关键词硬触发；
- `boundaries`：不适用或需要人工判断的情况；
- `deliverables`：必须交付的中间结果或最终结果；
- `acceptance_gates`：验收时需要的新鲜证据；
- `cost`：预估的上下文、搜索或工具成本。

许可证限制意味着该仓库不作为 MakeCrew 的运行时依赖，也不随 MakeCrew 自动安装。需要使用其原始 Skill 时，应由用户单独选择并在使用场景中遵守其许可证、外部服务和费用说明。

## 选择规则

1. 任务不清时不加载方法目录，先完成需求澄清。
2. 任务清楚后先返回当前领域的本地方法和匹配理由。
3. 只有本地无匹配、用户明确要求最新研究或存在能力缺口时，才扩展宿主搜索。
4. 方法卡不会自动创建员工、安装 Skill 或调用外部付费服务。
5. 任务完成后用验收证据判断方法是否有效，失败或返工才进入自进化提案。

发现接口会先规范化全部宿主候选，再按任务信号排序；`returned_count` 只是当前展示窗口（最多 8 张），
`external_result_count` 保留搜索器返回的总数。这样既避免首屏塞入过多上下文，也不会把展示窗口误解为
“只检索了这些结果”。候选缺少必需字段时会被跳过并计入无效结果统计，其他有效候选继续参与排序。
内置目录可用 `makecrew method-audit` 做发布前检查。
