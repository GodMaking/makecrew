# 自动触发与新对话入口

MakeCrew 的自动触发分为两层：Skill 匹配负责发现能力，全局任务入口负责保证新对话先完成需求分流。两层同时启用，才能兼顾便捷、准确和 Token 成本。

## Codex 安装

把仓库交给 Codex 后，先读取 `skills/makecrew/SKILL.md`、`skills/task-intake/SKILL.md` 和本页。确认 Codex Home 后执行：

```bash
makecrew install-codex-global-intake --codex-home CODEX_HOME
```

命令只在 `AGENTS.md` 追加带有 `MAKECREW:GLOBAL-INTAKE` 标记的规则：

- 已有内容保留不动；首次修改会生成 `AGENTS.md.pre-makecrew.bak`
- 重复执行不会重复追加
- 规则变化后重启 Codex，确保新的指令链在新会话启动时加载

## 用户怎么触发

### 主动触发

在 Codex 输入：

```text
$makecrew
```

或：

```text
$task-intake
```

然后描述任务。宿主会先判断需求是否清楚，检查本地 Skill、工具、方法和项目记忆，再决定直达、追问、组建临时专家组或进入 CEO 批次。

### 自动触发

当任务文字匹配 `makecrew` 或 `task-intake` 的 Skill 描述时，Codex 会尝试自动加载对应 Skill。自动匹配适合补充主动触发，但它依赖模型判断，不是固定钩子。

安装全局入口后，新对话的多步骤任务默认遵循：

```text
需求
 -> 需求分流
 -> 需要时逐轮追问（每轮 1-3 个，总数 0-N）
 -> 匹配 Skill、工具和方法
 -> 输出方案、成本、风险和验收标准
 -> 用户确认
 -> 执行、验收、交付
```

用户明确说“直接执行”“你决定”或“按默认值执行”时，可用 AI 默认值补齐剩余细节并开始执行。简单查询、读取、状态检查和小型可回退修复仍可直达。

## 安装后验证

新建一个对话，输入：

```text
我想做一个高级个人网站
```

正确结果应先出现关键问题或执行简报，内容至少包括：

- 对目标和交付物的理解
- 选用的 Skill、工具和方法
- 页面/工作流程和阶段交付物
- 验收标准、成本控制和主要风险
- 等待用户确认的执行门

再输入：

```text
按默认值执行
```

才进入文件创建、代码修改或其他实际操作。

## 其他宿主平台

Skill 的主动触发可以使用平台对应的 Skill 调用语法；自动触发和全局规则则使用该平台的系统指令、项目规则或工作区配置。MakeCrew 的核心契约保持一致：先澄清、匹配和给方案，再按确认门执行；平台没有全局指令机制时，使用 `$makecrew` 或等价的显式入口。
